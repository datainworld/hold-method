# 부록 B. 근거와 한계

## 근거 수준

HOLD v0.1의 원칙은 아래 근거를 조합해 정리한 실무 지침입니다. **HOLD 전체의 효과를 통제된 실험으로 검증한 결과는 아직 없습니다.** 키트의 테스트는 장치가 의도대로 동작한다는 것을 보여 줄 뿐, 개발 속도나 품질이 나아진다는 것을 보여 주지 않습니다.

| 주장 | 근거 수준 | 대표 근거 |
| --- | --- | --- |
| 분산은 비용과 복잡도를 높인다 | 강함 | Amazon Prime Video 모니터링 서비스 재구성 사례, Ghemawat et al., "Towards Modern Development of Cloud Applications" (HotOS '23) |
| 모듈 경계는 도구로 강제해야 유지된다 | 강함 | Shopify의 모듈러 모놀리스와 Packwerk |
| LLM은 입력이 길수록 성능이 불안정해진다 | 중간~강함 | Chroma, "Context Rot" 보고서 |
| 단계별 산출물 체인과 훅 기반 게이트가 AI 개발 흐름에 맞는다 | 실무 지침 | Anthropic, "The AI-Native SDLC playbook" (2026) |
| 이해관계자·관심사·관점으로 아키텍처를 기술한다 | 표준 | ISO/IEC/IEEE 42010 |
| AI 코딩에는 모듈러 모놀리스가 MSA보다 낫다 | 약함 | 실무자 에세이, 진행 중인 벤치마크 |
| 사람 소유 경계를 폴더 목록으로 정의하면 기술·의도·인지 부채가 줄어든다 | 가설 | HOLD 실증 예정 |
| 코딩 에이전트에게 최신 웹 가이드를 주면 권장 구현 방식을 더 따른다 | 제작사 자체 평가 | Modern Web Guidance 평가 (2026-11-08): Claude Code + Opus 5.5에서 57% → 88%. 제작사의 과제와 채점 기준이며, 앱 품질 전체가 아니라 권장 방식 준수율을 잰 값 (9.2) |
| 외부 가이드를 고정 버전으로 들이고 정책·버전을 사람이 소유하면 프런트엔드의 세 부채가 줄어든다 | 가설 | 웹 확장 web-0.1 실증 예정 |

## 알려진 한계 (v0.1)

- **Bash 우회.** `protect_paths.py`의 셸 검사는 휴리스틱입니다. 스크립트 파일을 거치거나 경로를 변수로 조립하는 방식은 잡지 못합니다. Regulated 프로필은 OS 수준 샌드박스로 보완해야 합니다.
- **도구 의존.** 경계·타입 검사는 `import-linter`, `pyright`가 설치되어 있어야 동작합니다. 없으면 훅이 조용히 건너뜁니다.
- **렌더 검사.** Mermaid 렌더링 검사는 `mmdc`가 있을 때만 동작합니다.
- **사실 뷰 범위.** v0.1이 생성하는 사실 뷰는 계약 클래스 뷰 하나입니다. 모듈 의존, 에이전트 그래프, ER은 v0.2 과제입니다.
- **1인 실증.** 첫 실증은 설계자 본인이 합니다. 확증 편향을 줄이기 위해 마찰을 먼저 기록하고, 판을 올리기 전 적대적 리뷰를 거칩니다(8장).
- **언어와 스택.** 키트는 Python 프로젝트와 Claude Code를 전제로 합니다. 원칙과 프로세스는 도구 중립으로 썼지만, 다른 스택에서 검증되지 않았습니다.
- **웹 확장.** 레거시 검사는 MWG 가이드의 약 20%만 다루고, 가이드 내용의 정확성은 MWG에 기댑니다. 확장 고유의 한계는 [9.11](09-web-frontend.md#911-알려진-한계-web-01)에 있습니다.
