# ADR 0001: 식당 추천을 dining 모듈로 분리한다

- 상태: 승인 · 날짜: 2026-11-08 (가상)
- 관련: [changes/20261108-dining/spec.md](../../changes/20261108-dining/spec.md)

## 배경
식당 추천은 관광지 추천(`places`)과 같은 가상 장소 API를 쓴다. places에 넣을지, 새 모듈로 둘지 정해야 한다.

## 선택지
1. `places`에 식당 범주를 추가한다
2. `dining` 모듈을 새로 만든다

## 결정
2번. 모듈 분할 네 질문 중 ①(업무 용어로 설명됨: "식사 조건을 지키는 식당 찾기")과 ③(바뀌는 이유가 다름: 식사 조건 규칙 vs 관광지 평가 기준)이 분리를 가리킨다. ②(외부 자원)는 같은 API를 공유하지만, 가장자리 코드는 각 모듈의 `_internal/`에 따로 둔다.

## 결과
- 식사 조건의 주인(SH-U02)이 바뀌면 dining만 바뀐다.
- 장소 API 호출 제한(분당 60회)은 두 모듈이 나눠 쓴다. 제한에 걸리면 platform 층에 공용 호출 상한을 두는 것을 검토한다.
