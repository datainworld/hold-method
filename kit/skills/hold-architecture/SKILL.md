# HOLD 아키텍처 규칙

원칙: **MSA처럼 설계하고, 모놀리스처럼 배포하고, 운영 특성이 갈라질 때만 쪼갠다.**

## 모듈을 새로 만들지 판단 (네 질문)
1. 업무 용어로 한 문장에 설명되는가?
2. 자기만의 외부 자원(API, DB, 파일)이 있는가?
3. 바뀌는 이유가 하나인가? (다른 모듈과 바뀌는 이유가 다른가?)
4. 에이전트가 한 번에 읽을 만한 크기(파일 몇 개)인가?
세 개 이상 "예"면 새 모듈을 제안하고, `docs/adr/`에 ADR 초안을 쓴다. 확정은 사람이 한다.

## 모듈 구조
- `app/modules/<이름>/api.py` — 유일한 공개 창구. 얇게: 로그, 내부 호출, 불변조건 강제
- `app/modules/<이름>/_internal/` — 비공개 구현
- `app/modules/<이름>/CLAUDE.md` — 목적, 맞닿는 이해관계자, 공개 함수, 불변조건, 하지 않는 것 (양식: `docs/hold/templates/module-CLAUDE.md`)
- 모듈끼리는 import하지 않는다. 조율은 `app/agent/`가 한다.

## 계약 (Stage 2.5 계약 게이트)
- 계약은 **모듈 사이 이음매에만** 둔다: 모듈 api의 입출력, 코디네이터 State, LLM 구조화 출력, 외부 API·DB와 맞닿는 데이터.
- **너 스스로 정하지 말고, 질문으로 남겨라.** 단위·통화, None의 의미, 허용 범위, 실패 방식, 누가 계산하는지(LLM/코드)는 사람이 결정한다.
- 초안은 변경 폴더의 `changes/<폴더>/contract_draft.py`에 쓴다. `app/contracts/`는 보호 경로라 쓸 수 없고, 초안을 그리로 옮겨 확정하는 것은 사람이 한다.
- 외부 시스템에 명세(OpenAPI 등)가 있으면 그것에서 모델을 생성하고, 사람은 의미만 확인한다.
- 계약 4층: 형태(타입), 허용 범위(`Field(ge=…)`, `extra="forbid"`), 의미(`description`), 실패 방식(예외 이름 또는 실패 결과).
- 합계·정렬·필터처럼 계산으로 정해지는 값은 `computed_field`나 코드로. LLM에게 계산을 맡기지 않는다.

## 데이터 소유
- 데이터는 소유 모듈만 읽고 쓴다. 다른 모듈은 공개 함수로 받는다.
- LLM이 만든 SQL은 실행하지 않는다. 고정 SQL + 매개변수 바인딩 + 읽기 전용 연결.
- PostgreSQL은 모듈별 스키마와 계정으로 나눈다.

## 통신
- 모듈끼리는 함수 호출. 네트워크는 외부 시스템과 맞닿는 가장자리에만 둔다.
- 가장자리에는 재시도·호출 상한·"실패 메시지를 결과로 돌려주기"를 한곳에 둔다.
- 사용자 응답과 무관한 비동기 작업만 Outbox(DB 테이블 + 워커)로. 처리 함수는 멱등.

## 서비스로 떼어낼지 (운영 특성이 갈라질 때만)
하드웨어가 다른가(GPU 등), 확장 패턴이 다른가, 장애 격리가 필요한가, 배포 주기가 다른가 — 하나라도 "예"면 그 모듈만 검토하고 ADR을 쓴다.
