# HOLD 확장 (실험)

> 상태: **제안.** 이 폴더는 동결된 HOLD v0.1 방법론의 일부가 아닙니다. 확장 규약을 8장(개정 규칙)에 넣을지는 v0.2 회고에서 정합니다 ([ADR 0002](../method-adr/0002-web-extension-mwg.md)). 편입 준비물은 [web/v0.2-merge/](web/v0.2-merge/README.md)에 있습니다.

확장은 코어가 다루지 않는 기술 영역(예: 웹 프런트엔드)에 HOLD의 원칙을 적용하는 바인딩 묶음입니다. 문서, 키트 장치, 테스트로 이루어집니다.

| 확장 | 판 | 내용 |
| --- | --- | --- |
| [web](web/README.md) | web-0.1 (2026-11-12) | 웹 프런트엔드. Google Chrome의 Modern Web Guidance를 고정 버전으로 들이고 정책·버전·허용 목록을 사람이 소유하게 한다 |

## 확장 규약 (제안)

**확장은 코어를 고치지 않는다.** 이것이 규약의 중심입니다. 처음 만든 웹 확장은 이 원칙 없이 코어 파일 8개와 8장을 고쳤습니다. 적대적 리뷰가 그 점을 "동결을 우회하는 통로"(ADV-13)로 지적했고, 그래서 이 규약이 생겼습니다.

1. **원칙을 바꾸지 않는다.** H1~H10은 그대로이고, 확장은 원칙을 새 영역에 적용하는 방법만 정한다.
2. **코어 파일을 바꾸지 않는다.** 코어는 `method/`, `kit/`, `tests/`, `examples/`, `method-adr/0001-*.md`이다. [`core-v0.1.sha256`](core-v0.1.sha256)에 동결 시점의 내용 해시가 있고, 각 확장의 테스트가 `core_manifest.py`로 이것을 검사한다. 코어를 고쳐야만 되는 일은 확장이 아니라 v0.1.x 패치나 v0.2의 일이다.
3. **프로젝트에 붙을 때도 코어 키트가 설치한 파일을 고치지 않는다.** 확장은 자기 훅 파일을 별도 항목으로 등록하고, 자기 보호 경로는 스스로 지킨다. 프로젝트 파일(`hold.toml`, `CLAUDE.md`, `.claude/settings.json`, 양식 사본)에는 표식이 붙은 절을 덧붙이기만 한다.
4. **규칙 번호는 R14부터 잇는다.** 통제 대응표에 장치와 강제 수준을 정직하게 적는다 (H7).
5. **발행 전에 적대적 리뷰를 받는다.** 작성에 관여하지 않은 검토자가 실제로 공격해 보고, 그 원문과 처리 결과를 방법론 ADR에 남긴다.
6. **실증과 섞지 않는다.** 실증 중인 프로젝트에서 확장을 켜는 것은 그 프로젝트의 변경(intent)이다. 확장의 측정은 별도 시트에 적어, 코어 v0.1의 실증 결과와 구분한다.

```bash
python extensions/core_manifest.py --check   # 코어가 동결 시점과 같은지
```

## 동결과의 관계

- 코어 v0.1은 2026-11-09에 동결되었습니다. 이 폴더의 내용은 코어 판을 바꾸지 않으므로, 동결 중에도 더할 수 있습니다.
- 다만 "확장"이라는 이름이 동결의 구멍이 되지 않도록 조건 2를 기계로 검사합니다. 매니페스트를 다시 쓰는 일(`--write`)은 코어 판을 올릴 때만, 사람이, ADR과 함께 합니다. 매니페스트 변경은 PR 차이에 그대로 드러납니다.
