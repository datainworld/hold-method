# v0.2 편입 체크리스트

## 편입 여부 판정 (회고에서)

- [ ] 1차 실증이 끝났고, 이 확장을 쓴 프로젝트(웹 UI가 있었는지)가 있다. 없었다면 **편입하지 않고** 2차 실증 때 시험한다.
- [ ] `docs/hold/web-measurement.csv`와 마찰 기록에서 다음을 확인했다.
  - [ ] 에이전트가 오래된 패턴을 쓴 사례를 레거시 검사나 가이드가 실제로 줄였다(R15·R16).
  - [ ] 설치·사용 비용(마찰 기록의 "비용")이 감당할 만하다.
  - [ ] 사람이 정책을 정하는 절차(사용 환경 → baseline)가 실제로 쓰였다(R14).
  - [ ] 래퍼 때문에 막힌 정상 작업이 있었는지, 있었다면 규칙을 고쳤다(R17).
- [ ] 규칙마다 유지·수정·삭제를 판정했다. R18(안내만)은 실제로 깨졌는지 본다.
- [ ] 훅(`--with-guard`)을 쓴 프로젝트가 있었고, 훅이 막은 실수의 사례가 있다. **사례가 없으면 훅은 편입하지 않는다.**
- [ ] MWG가 계속 유지되는지(1.x 이후 버전, 하위 명령, 패키지 구조 변화)를 확인했다. 바뀌었다면 `sync.py` 변환부터 고친다.
