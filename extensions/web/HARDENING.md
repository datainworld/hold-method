# HOLD 웹 확장 web-0.1 — 강화: 실행 시점 훅 (선택)

> [README](README.md)의 "선택: 실행 시점 훅"에 해당합니다. `python extensions/web/install.py --target … --with-guard` 로 설치할 때만 씁니다. 방법론 통합(기본 설치)은 훅 없이 성립합니다.
> 결정 기록: [ADR 0002](../../method-adr/0002-web-extension-mwg.md) · 적대적 리뷰 원문: [1차](../../method-adr/0002-adversarial-review.md), [2차](../../method-adr/0002-adversarial-review-2.md), [3차](../../method-adr/0002-adversarial-review-3.md)

## 1. 위협 모델과 방어선

이 확장이 막으려는 상대는 **실수하는 협조적 에이전트**입니다. 지시를 따르려 하지만, 학습된 습관대로 `npx`를 부르거나, 지원 정책을 CLAUDE.md에 적어 넣거나, 검사를 통과시키려고 코드를 비트는 에이전트입니다. 사람(Neo)이 2026-11-12에 이렇게 정했습니다. 코어 v0.1의 R01이 "강제 (Bash는 휴리스틱)"인 것과 같은 전제입니다.

이 전제에서 방어선은 세 겹입니다.

| 겹 | 장치 | 무엇을 막나 | 무엇을 못 막나 |
| --- | --- | --- | --- |
| 1. 실행 시점 | `web_guard.py` (PreToolUse·PostToolUse), 래퍼 `mwg.py` | 흔한 실수와 흔한 셸 형태: 직접 `npx` 호출, 설정 하위 명령, 보호 파일 쓰기(글롭·대소문자·`git --output` 포함), 레거시 패턴, 검사 우회 옵션 | 문자열을 조립·인코딩해 실행하는 코드 같은 의도적 우회 |
| 2. 커밋 시점 | pre-commit `hold-web-check`·`hold-web-legacy-scan` | 1겹을 지나간 결과물: 바뀐 생성물(검증된 사본으로 다시 만들어 대조), 바뀐 확장 코드(매니페스트), 정책 미동기화, 조용한 비활성화 | 프로젝트 안의 검사 코드와 매니페스트를 함께 바꾼 경우 |
| 3. 서버 쪽 | **CI**: `sync.py --fetch-only` → `install.py --verify` (저장소의 원본 코드로 검사) | 2겹까지 지나간 것. CI는 에이전트 세션 밖에서, 신뢰할 수 있는 원본 코드로 돌기 때문 | — (최종 방어선) |

**의도적인 우회를 막는 최종 방어선은 서버 쪽 CI입니다.** 로컬 pre-commit도 `.git/hooks` 수정이나 `git commit -n` 같은 방법으로 꺼질 수 있어(훅이 막는 것은 알려진 방법뿐), 로컬 검사는 방어선이 아니라 조기 경보입니다. 1·2겹은 에이전트가 실수로 선을 넘지 않게 하고, 넘었을 때 빨리 알리는 장치입니다. 적대적 리뷰 1·2·3차가 의도적인 공격을 가정하고 찾아낸 우회 중 상당수는 이 전제에서 1·2겹이 막도록 고쳤고(ADR 0002), 남는 것은 11절에 적었습니다. 의도적인 에이전트까지 실행 시점에 막으려면 훅이 아니라 OS 수준 통제(샌드박스, 읽기 전용 마운트, 권한 거부)가 필요합니다. 이것은 v0.2 안건입니다.

## 2. 훅이 하는 일 (`web_guard.py`)

**실행 전 (PreToolUse)**
- 편집 도구로 보호 경로를 쓰려 하면 막습니다. 경로는 대소문자, 구분자, NTFS 대체 스트림(`::$DATA`), 끝의 점·공백을 정규화해 비교하고, 같은 파일을 가리키는 다른 표기도 같은 파일로 봅니다. `.mwgrc`는 프로젝트 밖(예: `~/.mwgrc`)도 포함합니다.
- Bash 명령을 셸 문법으로 해석합니다. 다루는 문법은 따옴표, `&&`·`||`·`|`·`;`·`&`, 줄 이음, 리다이렉트, `$(…)`·백틱·`<(…)`·`>(…)`, `bash -c`·`eval`, 감싸는 명령(`env`·`xargs`·`timeout`·`nohup` 등), `npx -c`·`-p`입니다.
  - **MWG를 `npx`·`npm`·`node`·바이너리로 직접 부르면 고정 버전이어도 막고**, 래퍼를 쓰라고 안내합니다. 실행 명령에 패키지 이름이 있는데 해석되지 않으면 막고, 표준입력을 읽는 셸·`source`·명령어 자리의 변수/글롭이 node 계열 이름과 함께 보여도 막습니다. 정적으로 해석되는 호출 위주이며 모든 동적 조립을 막지는 않습니다(11절). `grep`·`git`·`echo` 같은 언급은 예외입니다.
  - 보호 경로 판정은 글자 그대로의 언급, **글롭 패턴**(`.c?aude/…`, `hold.to?l`, `*`), 중괄호 전개, `--opt=경로` 형식, 대소문자 변형을 모두 봅니다. 보호 경로를 건드리는 명령은 읽기 전용 명령(`cat`, `grep`, `ls` 등)과 출력 옵션 없는 `git diff/log/show`, 그리고 래퍼·검사 스크립트 실행만 허용합니다.
  - `sync.py`·`install.py` 실행, `git commit --no-verify`·`-n`, `core.hooksPath`는 막습니다.
- **지난 훅 이후 바뀐 파일을 검사합니다.** 백그라운드 실행이나 실패한 명령이 바꾼 파일도 다음 도구 호출에서 잡힙니다.

**실행 후 (PostToolUse)**
- 지난 훅 이후 바뀐 프런트엔드 파일을 레거시 검사하고, 바뀐 `changes/` 산출물의 참조 가이드를 검사합니다. 편집 도구든 Bash든 같습니다.

**변경 감지와 검사 방식**
- 프런트엔드 파일과 `changes/` 산출물의 지속 스냅샷(`.hold/logs/web_snap.json`)을 내용 해시로 비교합니다(1MB 넘는 파일은 ctime 포함 메타데이터). `touch -r`로 mtime을 되돌려도 잡힙니다.
- 대상 파일을 임시 폴더에 중립 이름(`f0001.js` 등)으로 복사해 검증된 사본으로 검사합니다. 그래서 `.gitignore`, 파일 이름(`-x.js`), MWG 내부 제외 규칙(`test/`, `*.min.js` 등)의 영향을 받지 않습니다. Jinja 템플릿(`.j2`, `.jinja`, `.njk`)은 HTML로 검사합니다.
- 훅 자체가 예외로 죽으면 막는 쪽(종료 코드 2)으로 끝납니다. 로그는 ASCII로 써서 이상한 파일 이름에도 깨지지 않습니다.

## 3. 알려진 한계 (훅·우회)

- **위협 모델의 한계.** 실행 시점의 Bash 판정은 셸 해석기 기반이며 **정적으로 해석되는 호출만** 막습니다. 명령어 자리의 변수·글롭·중괄호는 node 계열 이름이 보일 때만 막고, 그 밖의 동적 조립은 fail-closed가 아닙니다(3차 리뷰 ADV3-06). 문자열을 조립하거나 인코딩해 실행하는 코드(예: Python `exec`, 변수로 만든 경로), 같은 명령에서 정의한 함수, 현재 폴더(`cd`)에 따라 뜻이 바뀌는 상대 글롭은 실행 전에 다 잡지 못합니다. 그 결과로 생성물·확장 코드·정책이 바뀌면 커밋 검사가 잡고, 프로젝트 안의 검사 코드까지 바뀌면 CI가 원본 코드로 잡습니다. 실행 시점에 의도적 우회까지 막으려면 OS 수준 통제가 필요합니다(v0.2 안건).
- **코어 훅의 같은 약점.** 2차 리뷰가 찾은 `git --output`, 글롭, 대소문자 변형 우회는 **코어 v0.1의 `protect_paths.py`에도 그대로 통합니다.** 확장은 자기 보호 경로와 `hold.toml`·`.claude/`에 대해서만 더 엄격하게 판정하고, 코어 파일은 고치지 않았습니다. 코어의 다른 보호 경로(`app/contracts/`, `tests/golden/` 등)는 여전히 이 우회에 열려 있습니다. v0.1.x 결함 또는 v0.2 안건으로 다뤄야 합니다(ADR 0002).
- **알려진 우회 방지의 범위.** 훅은 `git commit -n`류 단축 옵션, `--no-verify` 약어, `GIT_CONFIG_*`·`SKIP=` 환경변수, `.git/hooks`·`.git/config` 수정, `pre-commit uninstall`, 증거를 지우는 `git clean`·`reset --hard`·`checkout .`·`stash -u`를 막습니다. 이것도 목록 기반이라 새 방법은 통과할 수 있고, 그 경우 서버 쪽 CI(`install.py --verify`, `web_check.py`, `web_scan.py`)만 남습니다. `.npmrc`·`package.json`·`CLAUDE.md`·`.gitignore`는 보호하지 않습니다(직접 npm 호출이 막혀 있고 scan은 임시 사본으로 하므로 영향이 제한적이라고 판단. 3차 ADV3-07).
- **검사 범위.** 레거시 검사는 가이드의 약 20%만 다룹니다. 나머지는 안내(skill)에 머뭅니다.
- **R14의 빈틈.** 정책 원본과 `.mwgrc`는 지켜지지만, 에이전트가 CLAUDE.md에 정책 같은 문구를 쓰는 것은 막지 못합니다.
- **R16의 빈틈.** 프런트엔드 파일이 바뀐 변경에서 "생략: 이유"를 쓰는 것을 막지 못합니다(변경 폴더와 코드 변경의 연결이 v0.1에 없음). `since` 판정은 Git에 처음 들어온 날짜를 보므로 Git 밖 프로젝트에서는 폴더 이름의 날짜만 봅니다.
- **스냅샷의 범위.** 변경 감지는 훅이 돌 때 일어납니다. 검사에서 문제가 난 파일은 고쳐질 때까지 스냅샷에서 빼서 다음 훅에서도 다시 보고하고, `git commit`·`push` 직전의 Pre 훅은 문제가 남아 있으면 막습니다(그 밖의 명령은 고치는 작업이므로 막지 않음). 스냅샷이 지워지면 다음 훅은 프런트엔드 전체를 검사합니다. 마지막 도구 호출 뒤에 백그라운드로 바뀐 파일은 다음 호출이나 커밋·CI에서 잡힙니다. 사람이 세션 밖에서 고친 파일도 다음 훅에서 검사 대상이 됩니다.
- **로그의 신뢰.** 훅 로그는 확장이 보호하지만 해시 체인은 없습니다. 측정 근거로는 충분하되, 감리 증거로 쓰려면 Regulated에서 로그 보존 방식을 따로 정해야 합니다.
- **원본 형식 의존.** `sync.py`는 원본 `SKILL.md`의 실행 명령 형식과 패키지 구조에 기대어 변환합니다. 바뀌면 설치를 멈춥니다.
- **비용.** 웹 확장을 켜면 도구 호출마다 훅이 두 번(전·후) 돌고, 프런트엔드 파일 스냅샷과 사본 해시 대조(사본 약 17MB)를 합니다. 큰 프런트엔드에서는 지연이 생길 수 있습니다.
- **사람이 직접 실행할 때.** 사람이 터미널에서 MWG를 래퍼 없이 실행하면 텔레메트리 설정은 셸에 따릅니다.
- **접근성 인증과 프레임워크.** KWCAG 항목은 다루지 않습니다. React·Vue 등에는 가이드의 적응 지침만 있습니다.
- **근거 등급.** 실증 0회. 모든 규칙의 근거 등급은 가설입니다.


## 4. 크기와 판단

훅 장치(`web_guard.py`, `common.py`의 셸 해석·스냅샷, 매니페스트)는 방법론 통합 코드보다 크고, 적대적 리뷰를 3번 거쳤습니다. 그래도 위협 모델이 "실수하는 협조적 에이전트"이므로 새 우회가 계속 나올 수 있고, 의도적 우회는 OS 수준 통제 없이는 막을 수 없습니다. 그래서 기본 설치에서 뺐습니다. 1차 실증에서 에이전트가 실제로 선을 넘은 사례가 있을 때만 켜고, 유지·축소·삭제는 v0.2 회고에서 정합니다.
