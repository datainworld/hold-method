# 방법론 ADR 0001: 이름, 구조, 공개 방식

- 상태: 승인 · 날짜: 2026-11-06 · 판: v0.1

## 배경

AI-Native SDLC 플레이북(흐름)과 내부 가이드 "AI-friendly 모듈러 아키텍처 7원칙"(구조)을 흡수 연구한 결과를 바탕으로, 독립된 개발방법론을 만들어 실증으로 개정해 나가기로 했다. 흡수 연구 중 두 가지를 보완했다: 이해관계자(사람과 연관 시스템) 식별과 영향 분석, 단계별 필수 다이어그램.

## 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 이름 | HOLD (Human-Owned Loop Development) | 가장 고유한 아이디어("사람이 소유한 선을 폴더 목록으로 정의하고, 그 안에서 AI 루프를 돌린다")가 이름에 들어감 |
| 부제 | 사람이 쥐는 AI-Native 개발방법론 | 검색성 보완, 한국어 독자에게 의도 전달 |
| "○○DD" 분류명 | 쓰지 않음 | Intent-Driven, Boundary-Driven 등은 이미 쓰이고 있음. HOLD는 실천 기법이 아니라 방법론 층위 |
| 구조 | 원칙·프로세스·키트·측정 4층 | 바뀌는 속도와 독자가 다름 |
| 키트 | 문서가 아니라 설치형 파일 묶음 (`hold-kit`) | "따르는" 방법론이 아니라 "강제되는" 방법론 (H7) |
| 프로필 | Lite 완전 정의, Standard·Regulated는 추가 항목만 | 1인 실증에서 방법론 비용이 이득을 넘지 않게 |
| 저장소 | 공개, 개인 계정, `hold-method` | 외부 피드백을 실증 장치로 사용 |
| 라이선스 | 문서 CC BY 4.0, 코드 Apache-2.0 | 출처 표시만으로 자유롭게 사용, 코드는 특허 조항 포함 |
| 7원칙 문서 | 4장으로 흡수, 예제는 가상 여행 가이드로 새로 씀 | 독립적으로 읽히게, 원 예제(강의 노트북 재구성)의 공개 저작권 부담 회피 |
| 용어 | 이해관계자 "정의서", "산출물" (등록부·아티팩트 대신) | 작성자의 용어 선택, 공공 SI 독자에게 익숙함 |
| 일정 | 동결 2026-11-09, 실증 1차 후 v0.2 | 가능한 한 앞당김 |

## 구현 중 바꾼 것 (초안 문서 대비)

- 설정 파일을 `hold.yaml` 대신 `hold.toml`로 했다. Python 3.11 표준 라이브러리(`tomllib`)로 읽을 수 있어 키트에 의존성이 생기지 않는다.
- 스킬 이름에 `hold-` 접두어를 붙였다(`hold-intent`, `hold-architecture`, `hold-views`). 사용자 환경의 다른 스킬과 이름이 겹치지 않게 하기 위해서다.
- 계약 초안의 위치를 `app/contracts/_draft_*.py`에서 `changes/<id>/contract_draft.py`로 옮겼다. `app/contracts/`는 보호 경로라 에이전트가 초안을 쓸 수 없었다(테스트 작성 중 발견). 초안이 변경 폴더에 함께 있어 산출물 체인도 한곳에 모인다.
- 통제 대응표에 R08(사실 뷰 최신성)을 더해 규칙이 13개가 되었다. 강제 8, 부분 2, 안내만 3.
- 수정 직후 검사를 훅 하나(`post_edit.py`)로 묶었다. 파일 종류에 따라 산출물 검사 또는 경계·타입 검사를 고른다.

## 결과

- v0.1은 실증 전 판이며 모든 원칙의 근거 등급은 "가설"이다.
- 다음 결정은 1차 실증(개인 AI 여행 가이드 앱) 회고에서 내린다. 두 번째 실증 프로젝트도 그때 정한다.
