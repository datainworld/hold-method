# 방법론 ADR 0002: 웹 프런트엔드 확장 — Modern Web Guidance 통합

- 상태: **검토 중** (3차 리뷰 반영판. 훅은 선택으로 분리, 4차 재검토는 훅을 켜기로 할 때 — 규약 5의 재검토가 끝나기 전에는 승인하지 않음) · 날짜: 2026-11-13 · 판: 코어 v0.1 (동결, 무수정) + 실험 확장 web-0.1
- 문서: [extensions/web/README.md](../extensions/web/README.md) · 확장 규약(제안): [extensions/README.md](../extensions/README.md)
- 첨부: [1차 적대적 리뷰 원문](0002-adversarial-review.md) · [2차](0002-adversarial-review-2.md) · [3차](0002-adversarial-review-3.md)

## 배경

- HOLD v0.1 키트의 통제 장치는 모두 Python 백엔드용이다. 웹 UI가 생기면 프런트엔드 코드에는 안내도 통제도 없다.
- 코딩 에이전트는 오래된 웹 구현 패턴을 쓰고, 그 코드는 동작하므로 테스트를 통과한다.
- Google Chrome 팀의 Modern Web Guidance(MWG) 1.0.0(2026-11-10)이 이 문제를 겨냥한다. 제작사 평가에서 Claude Code + Opus 5.5의 권장 방식 준수율은 57%에서 88%로 올랐다.
- 그러나 MWG를 그대로 들이면 HOLD 원칙과 부딪힌다. `@latest`, 정책을 바꾸는 여러 경로(`.mwgrc`, `set-baseline`, CLAUDE.md 제안), 사용자를 설득하라는 독촉, 그대로는 통제 장치가 아닌 `legacy-scan`, 텔레메트리가 그 예다(확장 문서 3절).
- 코어 v0.1은 2026-11-09에 동결되었고 1차 실증이 진행 중이다. 8장에 따라 실증 중에는 코어를 바꿀 수 없다.

## 경과

1. **초판** (PR #1 첫 커밋): "기본으로 꺼진 확장"이라는 이름으로 넣었지만, 실제로는 코어 키트 파일 8개(`protect_paths.py`, `post_edit.py`, `check_views.py`, `hold_init.py`, `settings.json`, 양식 3개)와 방법론 0·5·6·8장, 부록을 고쳤다. 8장에는 "확장" 정의를 새로 넣었다.
2. **적대적 리뷰**: 작성에 관여하지 않은 에이전트가 저장소만 보고 실제 공격을 실행했다. 결과는 16건(치명 2, 높음 5, 중간 6, 낮음 3)과 **병합 보류** 판정이었다. 치명 2건은 작성자가 따로 재현해 사실로 확인했다. 원문은 첨부에 있다.
3. **사람의 결정** (Neo, 2026-11-12): 세 방향 중 "코어 무수정 재설계"를 골랐다. 나머지 둘은 "현 구조 유지 + 결함만 수정(v0.1.1 패치로 표시)"과 "보류(v0.2 회고로)"였다.
4. **재설계** (PR #1 두 번째 커밋): 코어 파일을 모두 `main`으로 되돌리고, 확장을 `extensions/web/`으로 분리했다. 리뷰 16건을 반영하고 재현 공격을 회귀 테스트로 고정했다.
5. **2차 적대적 리뷰** (같은 검토자, 2026-11-13): 재설계판에서 새로 13건(ADV2-01~13, 치명 2·높음 4·중간 5·낮음 1 외 문서 정합)을 찾고 다시 **병합 보류**했다. 1차 해결 판정은 대부분 "부분 해결"로 낮아졌고, README·ADR의 "강제" 표기는 과장으로 지적되었다. 원문은 첨부에 있다.
6. **사람의 결정** (Neo, 2026-11-13): 위협 모델을 **"실수하는 협조적 에이전트 + 구조 보강"**으로 정했다. 훅은 실수를 잡고, 의도적 우회는 커밋 검사와 CI가 마지막으로 막는다. OS 수준 격리(샌드박스)는 v0.2 안건으로 미룬다. 완전한 차단을 약속하지 않는다.
7. **2차 재설계**: MWG 실행 경로를 하나로 줄였다(아래). 코어는 여전히 무수정이다.
8. **3차 적대적 리뷰** (같은 검토자, 2026-11-13): 새로 7건(ADV3-01~07: 높음 3·중간 3·낮음 1)과 문서 과장 6건을 찾고 **조건부 병합 보류**했다. 재설계가 필요 없고 높음 3건을 고치면 병합 가능하다는 의견이다. 원문은 첨부에 있다.
9. **3차 보강**: 아래 표대로 모두 수정하고 회귀 테스트를 더했다(165개). 문서의 "fail-closed"·"마지막 방어선" 표현을 정정했다.

## 2차 재설계 요지 (ADV2 반영)

- **검증된 사본 + 래퍼**: `sync.py`가 npm 무결성을 확인한 패키지를 `.hold/web-pkg/`에 저장하고 트리 해시를 `lock.json`에 남긴다. MWG는 `mwg.py`로만 실행하며, 래퍼가 매번 사본 해시를 대조하고 하위 명령을 제한하고 텔레메트리를 강제로 끄고 `retrieve` 출력에서 ID를 직접 기록한다. `npx`·`npm`·`node` 직접 호출은 훅이 막는다. (ADV2-03·04·05·10)
- **보호 경로 판정 강화**: 글롭·중괄호·대소문자·NTFS 변형을 정규화하고, git 쓰기 옵션(`--output` 등)과 `--no-verify`·`core.hooksPath`를 막는다. 해석되지 않는 명령은 fail-closed. 훅 예외도 차단으로 처리한다. (ADV2-01·02·08·12)
- **지속 스냅샷**: 내용 해시 스냅샷(`.hold/logs/web_snap.json`)을 매 훅에서 대조해 `touch -r`, 백그라운드 쓰기, 이상한 파일명으로 바뀐 파일도 다음 훅에서 잡는다. 레거시 검사는 중립 이름의 임시 사본으로 해 `test/`·`*.min.js` 제외 규칙을 피한다. (ADV2-06·07)
- **CI·커밋 방어선**: 확장 코드 `MANIFEST.json`, 재생성 대조를 저장된 tgz로 수행(npm 캐시 불필요), `install.py --verify`·`sync.py --fetch-only`로 원본 대조, pre-commit 항목 검사(주석 무시), R16 폴더명 규칙(`YYYYMMDD-이름`)과 git 추가일 기준 `since`. (ADV2-08·09·11)
- **정직한 표기**: R14~R18을 강제 0·부분 4·안내만 1로 낮춰 적었다. (ADV2-13)

### 공개: 코어 v0.1에도 있는 약점

git `--output`, 글롭, 대소문자 변형 우회는 코어 `protect_paths.py`에도 같은 방식으로 존재한다. 코어는 동결 중이라 이번 PR에서 고치지 않았다. v0.1.x 패치(작업을 막는 결함에 해당하는지 판단 필요) 또는 v0.2의 안건으로 올린다. 확장 훅은 자기 보호 경로만 지키므로, 코어 보호 경로(`.claude/` 등)는 코어 훅의 강도 그대로다.

## 선택지 (재설계 시점)

| 선택지 | 내용 | 판단 |
| --- | --- | --- |
| A. 현 구조 유지 + 결함 수정 | 코어 파일 수정은 v0.1.1 패치로 표시 | v0.1.x는 "작업을 막는 결함"만 고친다는 8장 규칙과 맞지 않는다. 확장이 동결의 구멍이라는 지적(ADV-13)도 남는다 |
| B. 보류 | PR을 draft로, v0.2 회고에서 결정 | 가장 보수적이다. 하지만 1차 실증에서 웹 UI를 붙이면 그 기간 내내 공백이 남는다 |
| **C. 코어 무수정 재설계** | 확장은 별도 폴더·별도 훅·별도 양식 조각으로만 붙이고, 코어 무수정을 기계로 검사한다 | **채택.** 동결을 지키면서 공백을 메운다. 실증 중인 v0.1 프로젝트에도 같은 절차로 붙는다(ADV-03 해소) |

## 3차 리뷰와 처리

| ID | 심각도 | 발견 (요지) | 처리 |
| --- | --- | --- | --- |
| ADV3-01 | 높음 | `mwg.py --limit install search`로 래퍼가 `install`·`update` 실행 (값 옵션 집합이 node와 다름) | 값 옵션을 `--skill-version` 하나로 맞추고, 하위 명령은 **첫 인자**여야만 허용 |
| ADV3-02 | 높음 | `git commit -nm` 등 단축 옵션·`--no-verif` 약어가 pre-commit을 건너뜀 | git 하위 명령을 해석해 `-n` 포함 결합 옵션과 `--no-verify` 접두 약어 차단 |
| ADV3-03 | 높음 | `GIT_CONFIG_*` 환경변수, `.git/hooks`·`.git/config` 수정, `pre-commit uninstall`로 커밋 검사 해제 | 해당 환경변수(`GIT_CONFIG*`·`GIT_DIR`·`SKIP`·`PRE_COMMIT*`·`HUSKY`)와 명령 차단, `.git/hooks/`·`.git/config` 보호 경로 추가 |
| ADV3-04 | 중간 | `git clean -fdx` 등이 `.hold/`(사본·스냅샷)를 지움 | `clean`, `reset --hard`, `checkout .`/`-f`, `restore .`, `stash -u` 차단. 스냅샷이 없어지면 첫 훅이 프런트엔드 전체를 검사 |
| ADV3-05 | 중간 | 위반이 1회만 보고되고 사라짐, 첫 훅은 기준선만 기록 | 문제가 난 파일은 스냅샷에서 빼 고쳐질 때까지 반복 보고. `git commit`·`push` 직전 Pre 훅은 문제가 남으면 차단 |
| ADV3-06 | 중간 | 변수·글롭·중괄호·`\| sh`·`source <(…)`로 직접 호출 | 표준입력을 읽는 셸·`source`·`eval`에 패키지 이름이 있으면 차단, 명령어 자리의 동적 표현에 node 계열 이름이 보이면 차단. **동적 조립 전체를 막는다고는 주장하지 않음** ("fail-closed" 표현 삭제) |
| ADV3-07 | 낮음 | `.npmrc`·`package.json`·`.gitignore`·`CLAUDE.md` 미보호 | **수용**: 직접 npm 호출이 막혀 있고 scan은 `.gitignore` 없는 임시 사본으로 하므로 영향이 제한적. `CLAUDE.md`는 R14의 알려진 빈틈. HARDENING.md 3절에 기록 |

리뷰가 지적한 문서 과장 6건은 HARDENING.md와 이 ADR에서 정정했다: 로컬 pre-commit은 방어선이 아니라 조기 경보이고 **서버 쪽 CI가 유일한 실질 방어선**이다. 검토자가 시간 안에 못 본 항목(SAVED_TO 위조, `--root` 리다이렉션, MANIFEST 자기 검증, 병렬 훅 경합, R16 `since` 회피, `legacy_allow` 글롭, `disabled_reason`)은 4차 재검토의 범위로 남긴다.

## 통합 확인 (실제 패키지, 2026-11-12~13)

키트 테스트는 가짜 `npx`·`npm`을 쓴다. 실제 `modern-web-guidance@1.0.0`과는 다음을 한 번 수동으로 확인했다(코어 v0.1 Standard 프로젝트에 설치).

1. `install.py` → `sync.py --pin 1.0.0`(npm에서 무결성 값 조회·검증) → `.mwgrc`·고정 skill·`guides.json`(208개)·`lock.json` 생성 → 사람 할 일(사용 환경, pre-commit)을 마친 뒤 `web_check.py` 통과. npm 캐시로 생성물 재생성 대조까지 통과.
2. `set-baseline limited` → 차단. `web/.mwgrc` 쓰기 → 차단. `CLAUDECODE= python3 .claude/hold-web/sync.py --tarball evil.tgz` → 차단. 같은 조작 패키지로 사람이 직접 실행해도 → "무결성 값이 다릅니다"로 중단.
3. 고정 skill의 "HOLD 프로젝트 규칙" 절을 지운 뒤 `web_check.py` → lock 해시 불일치와 재생성 불일치 둘 다로 실패. 루트가 아닌 `web/.mwgrc` → 실패.
4. heredoc으로 쓴 `web/viaBash.js` → 실행 후 검사로 차단(`ime-safe-enter-submit`). `-x.js` → 검출. `.gitignore`에 `web/`을 넣고 파일 6개 검사 → 검출. 차단 메시지의 가이드 읽기 명령에 `DISABLE_TELEMETRY=1`이 붙음.
5. 실제 `retrieve "dialog,ime-safe-enter-submit"`(출력이 파일로 저장됨) → 두 ID 모두 "확인됨"으로 기록. `echo "modern-web-guidance retrieve …"` → 기록 없음.

## 범위 조정과 4차 재검토

3차 뒤 Neo가 지적했다: HOLD 방법론 보완 단계에서 훅 보강이 과하다. 원래 의도는 "방법론에 MWG를 통합하고 취지와 통합 방법을 기술"하는 것이다. 그래서 확장을 두 단계로 나눴다(README 0절). **기본 설치는 훅 없이 방법론 통합만** 하고(`guard = false`: 고정 버전·정책·사용 환경·참조 가이드·커밋 시점 검사), 훅은 `--with-guard`로 켜는 선택으로 옮겼다(설계·위협 모델·한계는 HARDENING.md). 4차 재공격은 훅을 켜기로 할 때 한다. 3차에서 못 본 항목도 그때 포함한다. 결과와 처리는 이 절에 덧붙이고, 치명·높음이 남지 않을 때에만 상태를 "승인"으로 바꾼다.
