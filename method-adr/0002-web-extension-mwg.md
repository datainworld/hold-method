# 방법론 ADR 0002: 웹 프런트엔드 확장 — Modern Web Guidance 통합

- 상태: 승인 · 날짜: 2026-11-12 · 판: 코어 v0.1 (동결 유지) + 확장 web-0.1

## 배경

- HOLD v0.1 키트의 통제 장치(pyright, import-linter, Pydantic 계약, 계약·골든 테스트)는 모두 Python 백엔드용이다. 프로젝트에 웹 UI가 생기면 프런트엔드 코드에는 안내도 통제도 없다.
- 코딩 에이전트는 학습 데이터 때문에 오래된 웹 구현 패턴을 쓴다. 이런 코드는 동작하므로 테스트를 통과한다.
- Chrome 팀이 이 문제를 겨냥한 Modern Web Guidance(MWG)를 공개했다(1.0.0, 2026-11-10). 제작사 평가에서 Claude Code + Opus 5.5의 권장 방식 준수율이 57%에서 88%로 올랐다.
- 그런데 MWG를 그대로 설치하면 HOLD 원칙과 여덟 지점에서 부딪힌다(9.3). 매 호출 `@latest`, 지원 정책을 CLAUDE.md에 쓰자는 제안, 사용자를 설득하라는 업데이트 독촉, 종료 코드가 항상 0인 검사, 기본으로 켜진 텔레메트리 등이다.
- 코어 v0.1은 2026-11-09에 동결되었고, 1차 실증이 진행 중이다. 8장 규칙상 실증 중에는 코어를 바꿀 수 없다.

## 선택지

| 선택지 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 플러그인 설치 + CLAUDE.md 안내 | MWG 플러그인을 그대로 쓰고, CLAUDE.md에 주의사항만 적는다 | 가장 빠르다. 항상 최신 가이드 | H1·H7 위반. 정책·버전이 사람 손을 떠나고, 통제 장치가 없다. 실증 측정이 오염된다 |
| B. v0.2까지 미룸 | 마찰 기록만 하고, 회고에서 결정한다 | 8장 규칙에 가장 충실하다 | 1차 실증에서 웹 UI를 붙이면 그 기간 내내 공백이 남는다. 마찰 기록의 근거가 될 장치도 없다 |
| C. v0.2 조기 발행 | 코어를 개정해 웹을 포함한다 | 구조가 단순하다 | 실증 회고 없이 코어 판을 올리는 것은 8장 위반이다. 1차 실증 결과가 어느 판의 것인지 말할 수 없다 |
| D. 기본으로 꺼진 확장 + 고정 버전 바인딩 | 코어는 그대로 두고, 확장 web-0.1로 MWG를 고정 버전으로 들인다. 정책·버전·허용 목록은 사람이 소유하게 한다 | 코어 동결을 지킨다. 원칙을 새 영역에 그대로 적용한다. 켜는 시점을 프로젝트가 정한다 | "확장"이라는 개념이 8장에 새로 필요하다. 바인딩 코드를 유지해야 한다 |

## 결정

**D를 택한다.** 8장에 "확장"을 정의하고(다섯 조건, 동결과의 관계), 첫 확장으로 web-0.1을 낸다.

세부 결정은 아래와 같다.

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 들이는 방식 | 플러그인이 아니라 패키지에서 skill을 생성해 `.claude/skills/`에 둔다 (벤더링) | `.claude/`는 이미 보호 경로다. 어느 판의 지시를 따를지가 사람의 결정이 된다 |
| 고정 범위 | skill과 CLI를 같은 패키지 버전에서 고정 | 둘이 어긋나면 CLI가 업데이트 독촉을 보낸다. 같은 패키지에서 고정하면 독촉이 아예 생기지 않는다 |
| 정책의 원본 | `hold.toml [web]`. 생성한 skill에 옮겨 적는다 | 루트 CLAUDE.md는 보호 경로가 아니다(9.3 #1). CLAUDE.md 전체를 보호하면 "알려진 함정" 절을 갱신할 수 없다 |
| 원본 지시와의 충돌 | 원본은 고치지 않고 끝에 "HOLD 프로젝트 규칙" 절을 붙여 우선한다고 명시 | 원본 본문을 고치면 업스트림 변경을 따라가기 어렵다. 변환은 `@latest` 고정 하나로 최소화했다 |
| 변환 실패 | 원본에서 `@latest`를 못 찾으면 설치를 멈춘다 | 원본 형식이 바뀌었을 때 조용히 틀린 skill을 만들지 않는다 |
| 레거시 검사 강도 | 프로필에 따라 다르게: Lite는 기록, Standard 이상은 차단 | 범위가 20%뿐이고 오탐 판단이 필요하다. 1인 실증에서 차단부터 하면 마찰만 커진다 |
| 오탐 처리 | 사람이 `hold.toml`의 허용 목록에 적는다 | 에이전트가 검출을 없애려고 코드를 비트는 것("테스트를 고쳐 통과시키기"와 같은 구조)을 막는다 |
| 참조 기록 | spec의 `## 참조 가이드`에 ID를 적고, 고정 목록과 대조한다. 실제 `retrieve`는 훅 로그로 남긴다 | MWG의 응답 끝 공개 절은 에이전트의 말이라 증거가 아니다 (H9) |
| 텔레메트리 | 기본 끔. MWG 명령에만 `DISABLE_TELEMETRY=1`을 붙인다 | `settings.json`의 `env`에 두면 Claude Code 자체의 텔레메트리와 일부 기능까지 꺼진다 |
| 버전 변경 | 사람이 `hold_web_sync.py`로. Claude Code 셸 안에서는 실행을 거부한다 | R17. 거부는 `CLAUDECODE` 환경 변수에 기댄 휴리스틱이다 |
| 사용 환경 | 정의서 사람 행에 "사용 환경" 칸 | 지원 기준이 기술 선택이 아니라 "누구를 지원하나"의 결정이 되게 한다 (H3) |
| 대체 전략 선택 | 계약 질문으로 남긴다 (R18, 안내만) | 업무 결정이다. 다만 아직 이를 강제할 장치가 없다. 정직하게 "안내만"으로 표시한다 |

## 구현 중 바꾼 것

- **레거시 검사 기록을 코어 실패와 분리했다.** 처음에는 `hook: "post_edit"`로 남겼다. 그랬더니 Lite에서 기록만 한 검출이 측정 시트의 `check_failures`(에이전트에게 되돌린 실패)에 섞였다. 그래서 `hook: "web_scan"`으로 바꿨다.
- **"사용 환경" 칸 검사를 표의 열 제목으로 좁혔다.** 처음에는 파일 안에 "사용 환경" 문자열이 있는지만 봤다. 그랬더니 양식의 설명 문장 때문에 열을 지워도 통과했다(테스트에서 발견).
- **MWG 실행 기록용으로 PostToolUse 매처에 `Bash`를 더했다.** 확장이 꺼져 있으면 바로 끝나므로 코어 동작은 같다. 대신 Bash 실행마다 Python 프로세스가 하나 더 뜨는 비용이 생긴다.
- **비고정 호출 차단을 `protect_paths.py`(PreToolUse)에 넣었다.** 실행 후가 아니라 실행 전에 막아야 `@latest` 가이드가 컨텍스트에 들어오지 않는다. `grep` 같은 단순 언급은 차단하지 않도록, 같은 구간에 `npx`·`npm` 계열이 있을 때만 판정한다.

## 통합 확인 (실제 패키지, 2026-11-12)

키트 테스트(`tests/test_web.py`)는 가짜 `npx`와 가짜 패키지를 쓴다. 실제 `modern-web-guidance@1.0.0`과는 다음을 한 번 수동으로 확인했다.

1. `hold_init.py --profile standard --web` → `hold_web_sync.py`(npm에서 받음) → `--check` 통과. 가이드 208개, skill 버전 `2026_11_09-5bcc021b`.
2. 생성한 skill의 `search` 명령(`DISABLE_TELEMETRY=1 npx -y modern-web-guidance@1.0.0 search … --skill-version 2026_11_09-5bcc021b`)이 업데이트 경고 없이 결과를 돌려줬다. `--skill-version`을 2026-08-01로 바꾸면 60일 독촉 메시지가 나오는 것도 확인했다.
3. 레거시 패턴 7개를 넣은 시험 페이지를 `post_edit.py`에 넣었다. 실제 `legacy-scan`이 2건(`ime-safe-enter-submit`, `secure-external-subresources`)을 잡았고, 종료 코드 2와 고정 버전의 `retrieve` 명령을 에이전트에게 돌려줬다. div 모달, `body` 스크롤 잠금, 사용자 입력의 `innerHTML`, padding 비율 꼼수, 크기 없는 이미지는 잡지 못했다(9.2의 20% 범위).
4. `npx -y modern-web-guidance@latest search dialog`는 `protect_paths.py`가 R17로 막았다.
5. spec의 `## 참조 가이드`에 `ime-safe-enter-submit`(실재)과 `dialog-polyfil`(가짜)을 적었더니, `check_views.py`가 가짜 ID만 잡았다.

## 적대적 리뷰

8장 6단계는 판을 올리기 전에 작성에 관여하지 않은 에이전트의 "깨뜨려 보기" 검토를 요구한다. web-0.1은 코어 판을 올리지 않는 확장이라 발행 조건에는 넣지 않았다. **v0.2 회고 전에 이 검토를 받아 이 ADR에 첨부한다(미완).** 우선 볼 곳은 Bash 휴리스틱 우회, CLAUDE.md를 통한 정책 우회(R14의 빈틈), 허용 목록의 남용이다.

## 결과

- 코어 v0.1의 원칙·프로세스·규칙 R01~R13은 바뀌지 않았다. 코어 테스트 37개가 그대로 통과한다. 확장 테스트 41개를 더해 모두 78개다.
- 8장에 "확장"이 생겼다. 다음 확장(예: 데이터 파이프라인, 모바일)도 같은 다섯 조건을 따른다.
- 확장 규칙 R14~R18: 강제 2(R16, R17), 부분 2(R14, R15), 안내만 1(R18).
- 다음 결정은 1차 실증에서 웹 UI를 붙일 때 확장을 켜면서 시작한다. 회고에서 확장을 코어로 올릴지 판정한다.
